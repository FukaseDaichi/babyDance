# 表情・瞬き 設計

## 目的

キャラクターに瞬き・表情の切り替え・口の開閉を入れる。瞬きは不規則に、表情はダンスクリップごとに固定、口は拍に同期して開閉する。すべて拍の純関数として実装し、EditMode で決定的に検証できる形にする。

## 調査で判明した前提

実装方針はこの 4 つの事実から導かれている。推測ではなく、Blender と Pillow による計測結果である。

**キャラにブレンドシェイプは 1 つも無い。** `Assets/Characters/BabyBunny.fbx` は単一メッシュ `Bunny`（4997 頂点 / 10322 ポリ / マテリアル 1 / UV 1 / shape_keys None）、ボーンは Mixamo 標準の 33 本で顔ボーンはゼロ。

**目・口・眉・チークはすべてテクスチャに描かれている。目のジオメトリが存在しない。** したがって**ブレンドシェイプでは瞬きを作れない**。まぶたも眼球も無く、顔の表面を凹ませることしかできない。瞬きはテクスチャでしか表現できない。

**Meshy の UV は三角形単位に粉砕されている。** 2048² の BaseColor 上で顔は連続した島を成さず、数千の微小な島に散乱している。したがって **UV オフセットによる既存テクスチャの差し替えも、テクスチャの手描き修正も成立しない**。

**顔と髪は 1 つの連続面である。** 本体メッシュから顔ポリを切り出す方式はプロトタイプで検証して却下した。前髪のジオメトリが顔ポリと交互に並ぶため輪郭がギザギザになり、髪の房がパッチを貫通し、平面投影 UV に反転・退化ポリが 253 中 4 個出た。

## 方針

**顔の前に小さなデカール殻を 2 枚（目・口）置き、素の 0..1 平面 UV を持たせ、アトラスを `mainTextureOffset` で切り替える。**

デカール殻は格子平面を頭のメッシュへ shrinkwrap して曲面に沿わせたもので、プロトタイプで実証済み（336 ポリが顔の曲面に密着し、3/4 アングルでも剥がれない。UV の反転・重なりゼロ）。

**目と口を別レイヤーにする。** 表情 N コマ × 口 M コマで N×M 通りの顔が作れるため、アトラスの枚数が線形にしか増えない。1 枚に焼き込むと組み合わせの分だけ掛け算で増える。

**カスタムシェーダを持ち込まない。** 素の URP Lit（Transparent）と `MaterialPropertyBlock` だけで済む。UV2 + Shader Graph で本体マテリアルに重畳する方式は、ドローコールが増えず半透明ソートも無い上品な代替だが、シェーダ 1 本と法線マスクが増える。デカール方式で継ぎ目やソートが実際に問題になったときの次善手として残す。

**乱数を使わない。** 「一定周期でランダム」な瞬きは、決定的ハッシュで発火拍を散らして実現する。`CameraScore` の手ブレが正弦波の和で乱数を避けているのと同じ理由で、拍の純関数という性質と EditMode の決定的テストを保つため。

## 計測値

すべて FBX 単位（モデル全高 1.8979。Unity 側 `globalScale = 0.421515` で実寸 0.80 m）。正射影の正面レンダ（中心 z = 1.30、幅 0.70、1024²）を Pillow で解析して得た。

| 対象 | x | z |
| --- | --- | --- |
| 瞳（左右まとめて） | −0.1593 〜 +0.1572 | 1.1954 〜 1.2617 |
| 眉 | −0.1784 〜 +0.1825 | 1.3007 〜 1.3485 |
| 口 | −0.0479 〜 +0.0465 | 1.0901 〜 1.1776 |
| 頭のシルエット | −0.3500 〜 +0.3493 | 0.9507 〜 1.6500 |

正面レンダにおける瞳の暗画素数は **15,423 px**（判定条件: `lum < 60`、`250 < px < 780`、`520 < py < 700`）。この数値は検証の基準値として使う。

## アセットパイプライン

`tools/build_face_decals.py` を新設する。`blender --background --factory-startup --python` で実行し、`Assets/Characters/BabyBunny.fbx` を入力にデカール 2 枚を同梱した FBX を書き戻す。スクリプトはリポジトリに入れる（前回の Blender 往復はアドホックで再現性が残っていない）。

### デカール殻の作り方

1. 格子平面を顔の手前（`y = −0.6`。頭のシルエット最前面 −0.36 より確実に手前）に、後述の x / z 範囲で置く
2. 頭のメッシュへ +Y 方向に shrinkwrap（`wrap_method='PROJECT'`、`use_project_y`、`use_positive_direction`）
3. 法線方向に **0.0025** オフセット
4. 投影が当たらなかった頂点を削除する。**判定は「y が初期位置 −0.6 のままか」**（頭のシルエット外に飛んだ頂点は移動しないので元の平面上に残る）。プロトタイプでは 375 頂点中 37 個が該当した
5. UV は格子の素の 0..1 をそのまま使う。再展開は不要
6. **Data Transfer で本体メッシュから法線を転写する。** これをやらないとデカールは平面の法線を持ち、ライティングが本体とずれて継ぎ目が見える
7. 頂点グループ `mixamorig:Head` にウェイト 1 を与え、Armature モディファイアを付ける。SkinnedMeshRenderer として頭に追従する
8. 名前付きの空マテリアルスロットを 1 つ持たせる。Unity 側で `ModelImporter.AddRemap` により差し替えるため（`BabyBunny.mat` と同じ既存パターン。マテリアルを 1 つも持たない FBX は remap の識別子が存在せず差し替えられない）

### パッチの範囲

計測値にマージンを乗せた初期値。検証レンダが通らなければここを調整する。

| メッシュ名 | x | z | 格子 |
| --- | --- | --- | --- |
| `FaceEyes` | ±0.17 | 1.17 〜 1.29 | 16×8 |
| `FaceMouth` | ±0.09 | 1.06 〜 1.21 | 10×8 |

**眉はデカールに含めない。** 前髪のジオメトリが眉の帯（z ≈ 1.30〜1.35）に被さっており、プロトタイプで髪の房がデカールを貫通することを確認した。表情は目の形だけで担う。

## アトラス規約

### 目アトラス `Assets/Characters/FaceEyes.png`

512×256、4 列 × 2 行、コマ 128×128。

| # | 内容 | # | 内容 |
| --- | --- | --- | --- |
| 0 | 通常（開眼） | 4 | 半目 |
| 1 | 笑顔（^ ^ 型） | 5 | 閉眼 |
| 2 | 驚き（見開き） | 6 | 予備 |
| 3 | 得意げ（半月） | 7 | 予備 |

コマ番号は左上から右へ、次の行へ。

### 口アトラス `Assets/Characters/FaceMouth.png`

384×128、3 列 × 1 行、コマ 128×128。

| # | 内容 |
| --- | --- |
| 0 | 閉じ |
| 1 | 半開き |
| 2 | 大きく開く |

### 共通の制約

**半目（4）と閉眼（5）は全表情で共有する。** この画風では閉じた目は表情によらずほぼ同じ形になる。これによりコマ数が「表情数 × 3」の掛け算から「表情数 + 2」の足し算になる。加えて、ダンス切替時に表情が入れ替わっても閉眼中は見た目が変わらないという性質が得られる（後述）。

**各コマは瞳の領域で不透明でなければならない。** 半透明だと下に描かれた元の目が透ける。アルファはパッチの縁のフェザリングにだけ使う。

**コマ 128×128 の内側 120×120 に絵を置き、外周 4px を縁の複製で埋める。** ミップマップとバイリニアフィルタが隣のコマを拾って滲むのを防ぐパディング。テクスチャの `Wrap Mode` は `Clamp`、ミップは有効のまま。WebGL の DXT 圧縮は 4px ブロック単位で、コマサイズ 128 は 4 の倍数なのでブロック境界とコマ境界は一致する。

**コマ 0 の作り方。** 既存のボディテクスチャをデカールの平面 UV へ Blender でベイクすれば、現在の顔がピクセル単位で整合した無表情コマが得られる。残りのコマはこれを基準に作る。

## ランタイム構成

`CameraScore` / `ShotDirector` の関係をそのまま写す。

| 型 | 責務 |
| --- | --- |
| `FaceScore`（static class） | `PoseAt(beat, expression, switchBeat)` → コマ番号。および `AtlasRect(frame, cols, rows)` → UV 矩形。**両方とも純関数**。`System.Math` のみを使い Unity 非依存 |
| `FacePose`（struct） | `EyeFrame`、`MouthFrame`。純データ |
| `FaceDirector`（MonoBehaviour） | `FaceEyes` / `FaceMouth` の `SkinnedMeshRenderer` に `MaterialPropertyBlock` で `_BaseMap_ST` を書く。判断を持たない |

**`AtlasRect` を `FaceScore` 側に置く理由。** アトラスの行が上下反転する（UV の原点は左下、アトラス画像は左上始まり）のは古典的な事故である。`FaceDirector` に書くと EditMode から呼べず、総当たりで検証できない。実行時にしか分からない値に依存するガードを `CameraScore` 側の純関数に置いたのと同じ判断。

**`renderer.material` は使わない。** マテリアルのインスタンスを作って漏らす。`MaterialPropertyBlock` で `_BaseMap_ST` に `(tilingX, tilingY, offsetX, offsetY)` を書く。一般に tiling `(1/cols, 1/rows)`、offset `(col / cols, 1 − (row + 1) / rows)`。コマ番号は左上から右へ数えるが UV の原点は左下なので、行は反転する。目アトラス（4×2）なら tiling `(0.25, 0.5)`、コマ 0 の offset は `(0, 0.5)`。口アトラス（3×1）なら tiling `(1/3, 1)`、コマ 0 の offset は `(0, 0)`。

配線: `DancePlayer.Update` が `driver.Tick(beat)` → `shotDirector.Tick(beat)` → `faceDirector.Tick(beat)` を同じ拍で呼ぶ。`DanceClipInfo` に `expression`（int）フィールドを足す。`SceneBuilder.Build` が `FaceDirector` を配線する。

**観察用スイッチは付けない。** カメラの `Auto / Fixed` は演出の過剰に気づくために置かれたものだが、顔は目視で十分わかる。

## 譜面と定数

### 瞬き

n 回目の瞬きを `n = floor(beat / T)` とし、決定的ハッシュ `h(n) ∈ [0,1)` を使って発火拍を `n·T + h(n)·J` とする。乱数も履歴も持たないため拍の純関数のまま、見た目は不規則になる。

ハッシュは浮動小数に依存しない整数演算で書く（`sin` ベースのハッシュは環境差が出る）:

```csharp
static double Hash01(long n) {
    unchecked {
        ulong x = (ulong)(n * 2654435761L + 1013904223L);
        x ^= x >> 33; x *= 0xff51afd7ed558ccdUL;
        x ^= x >> 33; x *= 0xc4ceb9fe1a85ec53UL;
        x ^= x >> 33;
        return (x >> 11) * (1.0 / 9007199254740992.0);
    }
}
```

`n` は負にもなる（助走区間で `beat` が負のため `floor(beat / T)` が −1 になる）。`unchecked` と `ulong` へのキャストにより負の `n` でも定義通りに動く。

| 定数 | 初期値 | 120 BPM 換算 |
| --- | --- | --- |
| 平均間隔 T | 8 拍 | 4 秒 |
| 揺らぎ幅 J | 4 拍 | 2 秒 |
| 半目（前） | 0.1 拍 | 0.05 秒 |
| 閉眼 | 0.3 拍 | 0.15 秒 |
| 半目（後） | 0.1 拍 | 0.05 秒 |

発火拍からの位相で 半目(4) → 閉眼(5) → 半目(4) → 開眼(`expression`) と返す。

**不変条件: `J + 瞬きの全長 < T`。** 4 + 0.5 = 4.5 < 8 を満たすため、瞬きは隣の周期に食い込まない。したがって拍 `b` の判定では `n = floor(b / T)` だけを見ればよく、`n − 1` を考慮する必要がない。定数を変える場合はこの不変条件を維持すること。

### ダンス切替時の表情

表情が `DanceClipInfo` 由来だと、1 拍のクロスフェードの最中に顔だけ瞬間で切り替わる。

**切替拍で瞬きを 1 回強制発火させ、閉眼の裏で表情を差し替える。** `switchBeat ≤ beat < switchBeat + 0.5` の間は強制的に瞬きの位相を返す。

まだ一度も切り替えていない間は `switchBeat = double.NegativeInfinity` を渡す。この値では強制瞬きの条件が成立しないため、通常の瞬きだけが働く。

呼び出し側（`DancePlayer`）は切替後の `expression` をそのまま渡す。半目(4) と閉眼(5) は全表情で共有されるコマなので、切替の瞬間に見えるのは共有コマであり、**新しい表情の開眼コマが現れるのは閉眼が明けた `switchBeat + 0.5` である**。表情の入れ替わりは視覚的に隠れる。共有コマを採る設計判断がここで効いている。

### 口

拍の小数部 `f = beat − floor(beat)` で決まる。

| 条件 | コマ |
| --- | --- |
| `f < 0.15` | 2（大きく開く） |
| `f < 0.35` | 1（半開き） |
| それ以外 | 0（閉じ） |

拍の割合で持つため、BPM が上がるほど開閉が速くなる。音楽に乗るのが要件なので、これは正しい挙動である。

## 検証

### EditMode（`FaceScoreTests`）

各ガードについて「壊したら何が落ちるか」を先に決める。

| ガード | 壊し方 | 落ちるテスト |
| --- | --- | --- |
| 瞬きの揺らぎ | J = 0 にする | 発火間隔の**分散が 0 でない** |
| 瞬きの発火 | 発火条件を外す | 0〜1000 拍走査での発火回数が 1000/T の許容範囲 |
| 閉眼時間 | 0.3 を別の値にする | 各発火の閉眼幅 |
| 負拍の `floor` | ガードを外す | **−2 拍から開始する走査** |
| アトラスの行 | row を反転する | `AtlasRect` の全コマ総当たり |
| 切替時の強制瞬き | 呼び出しを消す | 切替拍直後に半目(4) が出ること |
| 表情と瞬きの合成順 | 順序を入れ替える | `expression` を変えると開眼コマだけ変わり、閉眼コマは共有されること |
| 口の範囲 | 範囲ガードを外す | 全拍走査で 0/1/2 以外を返さないこと |

**負拍のテストが重要である。** `PlayScheduled` の助走により拍は負から始まる（120 BPM で −2 拍）ため、`floor` を使う瞬き計算は負域を必ず踏む。

**フィクスチャは非対称にする。** 表情番号・アトラスの列数と行数・平均間隔と揺らぎ幅をすべて違う値にする。同じ値で組むと単位の取り違えも対象の取り違えも相殺して見えなくなる。

### PlayMode

`FaceDirector` が 2 つのレンダラを見つけられなければ例外で止まる。`ShotDirector` がボーンの無い Animator で例外を出すのと同じ型。

### アセット側の自動検証（`tools/verify_face_decals.py`）

`uv run` で実行する。Blender でレンダし Pillow で解析する。

**1. 元の瞳が 1 px も見えないこと**

デカールを不透明マゼンタで塗り、正面・±30°・±60° の 5 アングルをレンダする。判定は「**デカール無しで見えていた瞳画素のうち、デカール有りで残るもの = 0**」。

角度ごとにベースラインを取ること。±60° では顔が横を向いて瞳自体が見えなくなるため、絶対数で判定すると常に 0 になり網が死ぬ。デカールの帯を 1 cm 縮める変異で、正面の残存が 0 px → 数百 px になって落ちる。

**2. 髪の貫通**

同じレンダで、**デカール領域の縁から 4px 内側に髪色画素が 0** であること。閾値を推定で決めるのではなく「内側には 1 px も出ない」という意味の明確な条件にする。

**3. リグの無害性**

Blender 往復の前後で全 `HumanBodyBones` の minBoneY / maxBoneY が一致すること。前回の往復では −0.0392 / −0.0442 が完全一致した。デカール追加でボーンは変わらないはずなので、一致しなければ往復が何かを壊している。

### Editor

FBX に `FaceEyes` / `FaceMouth` の `SkinnedMeshRenderer` が存在し、マテリアルが remap されていること。Blender 側でメッシュ名を変えたときに落ちる。

### 自動では守れないもの

以下は目視でしか確認できない。仕様として明記する。

- **Data Transfer による法線転写を外しても、どのテストも落ちない。** ライティングの継ぎ目は目視でしか分からない
- 半透明のデカールの縁が浅い角度で本体に埋もれるかどうかも、検証レンダの目視
- ブラウザでの最終確認は「瞬きと口が拍に乗って見えるか」に絞る

## 実行環境

- Blender 5.2.0 LTS（`/opt/homebrew/bin/blender`）。パイプラインは `--background --factory-startup --python` で回す。`blender-mcp` はバックグラウンドモードを明示的に拒否する（`cannot start server in background mode`）ため、MCP は対話的な確認にのみ使い、再現性のある工程は headless スクリプトに置く
- Python は必ず `uv run`。PEP 723 のインラインメタデータで依存を宣言する
- Unity は `tools/unity.sh` を通す。`compile` / `test EditMode <期待件数>` / `exec <完全メソッド名>` / `build`
- GUI の Unity Editor が同プロジェクトを開いていると CLI は失敗する

## 既知の限界

- 眉は動かない。前髪のジオメトリと干渉するため、表情は目の形だけで担う
- 瞬きは常に同じ速度で、二連続瞬きのような変化は持たない
- 口は拍に対して機械的に開閉し、実際の音声とは無関係である
